# 隐私与合规红线

这个 skill 处理的是用户最私密的数据之一：他与 AI 的全部对话。红线不是建议，是硬约束。

## 四条硬约束

1. **只读不改**
   `collect_sessions.py` 只以读模式打开会话文件，绝不写入、移动、删除。不要为了"整理数据"去修改用户的历史会话目录。

2. **不出本机**
   三个脚本都没有网络调用（无 `requests`、无 `urllib` 请求、无上传）。新增功能时若需要联网，必须显式征得用户同意，并在输出里说明传了什么、传给谁。

3. **默认脱敏**
   采集时默认打码：邮箱、手机号、身份证、16-19 位长数字、`sk-`/`ghp_` 等密钥、URL 里的 token、本地用户名路径。用户要求关闭时才用 `--no-redact`，且要提醒风险。

4. **不索取凭证**
   绝不要让用户把 Cookie、账号密码、API Key 交给这个 skill。需要更多数据时，给用户可以自己在本机执行的命令（如 OpenCLI 的导出命令），由他自己跑、自己给文件。

## 输出物本身就是敏感文件

`yishi-corpus.json` 含原始消息（即使脱敏，也可能含商业信息、他人隐私、未公开判断）；`report-data.json` 和 `奕识报告.html` 含对用户的心理侧写。

因此：

- 默认只写本地目录，不建议也不自动上传到任何云端、群聊、公开链接
- 不要替用户把报告发到邮件或公众号，除非他明确要求
- 报告页脚已固定"本地生成，无数据上传"，不要删掉这句
- 提醒用户：这两个 JSON 不要提交进 git 仓库（`.gitignore` 已排除）

## 会话里会混进别人的隐私

微信/群聊/协作文档的对话被粘贴进 AI 会话后，就成了语料的一部分。处理原则：

- 证据样本只截取**用户本人的发言与主题词**，不引用对话另一方的原话
- 若样本里出现第三方姓名、公司内部信息、未公开交易细节，写报告时要替换为"某公司""某同事"
- 用户明确说"这段别写进去"的，从语料里剔除，并记下原因

## 不做的事

| 不做 | 原因 |
|---|---|
| 爬取第三方平台数据 | 违反平台条款；即使爬自己的数据，凭证进入服务端后责任在运营者（详见项目主目录 `结论摘要.md` 的合规评估） |
| 推断健康状况、性取向、政治倾向 | 与职业决策无关，属于超范围收集 |
| 给心理诊断结论 | 焦虑/滤镜是权重参数，不是临床判断；用户若表现出持续低落，建议寻求专业帮助而非继续调参 |
| 把报告当作招聘筛选依据 | 这是给个人用的自我认知工具，用于筛选他人属于就业歧视风险 |

## 平台差异提示

不同 Agent 的会话存储位置与格式不同，脚本靠"目录约定 + 字段兜底"兼容。若某个 Agent 更新了格式导致采集失败：

- 不要为了拿到数据而尝试破解加密存储
- 如实告诉用户"这个工具的数据暂时读不到"，退回 `--extra` 导入导出文件或对话式轻量版

## 用户知情的最小要求

跑采集之前，用一句话说清：**要读哪些目录、读什么内容、存在哪、不联网**。例如：

> 我会读取你本机 `~/.claude/projects`、`~/.workbuddy/projects` 等目录下的会话文件，只取你发的消息文本，脱敏后存在当前目录的 `yishi-corpus.json`，全程不联网。

用户说"别读某个工具"，就用 `--agents` 排除。这一步不能省，也不能用"你放心我很有分寸"代替。
